# Домашнее задание 3 — бюджеты, ввод-вывод и обработка ошибок

Расширенная версия Ledger из второго ДЗ. Вся логика третьего задания находится
в модуле `homework-3/ledger`. Gateway из `homework-2/gateway` запускается по инструкции второго
ДЗ и для проверки бюджетов не требуется.

## Файлы

| Файл | Назначение |
| --- | --- |
| `ledger/main.go` | Транзакции, бюджеты, загрузка JSON и демонстрация проверок |
| `ledger/go.mod` | Модуль `homework-3/ledger`, минимальная версия Go 1.22 |
| `ledger/budgets.json` | Начальные бюджеты категорий |
| `README.md` | Инструкция по запуску и ожидаемые результаты |

## Запуск

Требуется Go 1.22 или новее. Сторонних библиотек нет.

Распакуйте папку `homework-3` из архива в корень репозитория с домашними заданиями.
В терминале из корня репозитория выполните:

```sh
cd homework-3/ledger
go run .
```

В VS Code можно нажать правой кнопкой на `homework-3/ledger`, выбрать Open in Integrated
Terminal и выполнить `go run .`.

`go.mod` уже включён: повторять `go mod init` не нужно.

Запускайте программу именно из `homework-3/ledger`: относительный путь `budgets.json`
отсчитывается от текущей папки терминала. После демонстрации программа завершается.

## Учебная модель

- Транзакции — расходы; сумма должна быть строго положительной.
- Суммы и лимиты имеют тип `int` и измеряются в целых рублях.
- Бюджет фиксированный для категории, без периода и автоматического сброса по дате.
- Название категории сравнивается точно, с учётом регистра и пробелов.
- Для категории без бюджета положительные расходы разрешены.
- Расход ровно до лимита разрешён; превышение отклоняется до изменения хранилища.
- `SetBudget` добавляет или обновляет лимит, сохраняя уже совершённые расходы.
  При прямом вызове передавайте непустую категорию и неотрицательный лимит.
- Если новый лимит ниже существующих расходов, старые записи сохраняются,
  а новые расходы этой категории отклоняются.
- Данные хранятся в памяти. Следующий запуск начинает демонстрацию заново.
- Изменение бюджета через `SetBudget` не перезаписывает JSON-файл.

## Загрузка бюджетов

В `main` файл открывается через `os.Open("budgets.json")`, затем передаётся
в `LoadBudgets` через `bufio.NewReader`. Файл закрывается и при ошибке загрузки.

`LoadBudgets(r io.Reader) error` читает данные через `io.ReadAll` и разбирает их
через `json.Unmarshal`. Используется массив объектов с полями `category` и `limit`.

```json
[
  {"category": "Продукты", "limit": 5000},
  {"category": "Транспорт", "limit": 1000}
]
```

Пустой массив `[]` допустим. Пустой файл, `null`, неправильный JSON, пустая
категория и отрицательный лимит приводят к ошибке. Нулевой лимит допустим и
не разрешает положительных расходов этой категории. Лимиты указывайте целыми
числами; например, `5000`, а не `5000.5`.

При повторе категории в массиве применяется последний бюджет: это соответствует
обновлению через `SetBudget`. Загрузка добавляет/обновляет переданные категории,
а остальные существующие бюджеты сохраняются. Все объекты проверяются до записи
в хранилище, поэтому ошибка в файле не оставляет частично загруженные бюджеты.

Ошибки чтения и разбора возвращаются с контекстом через `fmt.Errorf` и `%w`.
`ErrBudgetExceeded` позволяет отличить превышение бюджета через `errors.Is`.

## Сценарии в main

Для поставляемого `budgets.json`:

| Действие | Ожидаемый результат |
| --- | --- |
| Продукты: 3000 при лимите 5000 | Добавлено, ID 1 |
| Продукты: ещё 2500 | Отказ: 3000 + 2500 > 5000 |
| Продукты: ещё 2000 | Добавлено, ID 2; сумма ровно 5000 |
| Транспорт: 800 при лимите 1000 | Добавлено, ID 3 |
| Связь: 700, бюджет не задан | Добавлено, ID 4 |
| Продукты: 0 | Отказ: сумма должна быть положительной |
| Обновление бюджета Продукты до 6000 | Новый лимит установлен |
| Продукты: ещё 1000 | Добавлено, ID 5; сумма ровно 6000 |

Ожидаемый вывод:

```text
Ledger service started
Загружено бюджетов: 2
Добавлено: Продукты, 3000 руб.
Отказ (Продукты, 2500 руб.): budget exceeded: категория "Продукты", доступно 2000 руб., запрошено 2500 руб.
Добавлено: Продукты, 2000 руб.
Добавлено: Транспорт, 800 руб.
Добавлено: Связь, 700 руб.
Отказ (Продукты, 0 руб.): сумма расхода должна быть больше 0

Увеличиваем бюджет категории Продукты до 6000 руб.
Добавлено: Продукты, 1000 руб.

Сохранённые транзакции:
ID: 1 | Продукты | 3000 руб. | 2026-09-30 | Покупка продуктов
ID: 2 | Продукты | 2000 руб. | 2026-09-30 | Ровно до лимита
ID: 3 | Транспорт | 800 руб. | 2026-09-30 | Оплата проезда
ID: 4 | Связь | 700 руб. | 2026-09-30 | Категория без бюджета
ID: 5 | Продукты | 1000 руб. | 2026-09-30 | Покупка после изменения бюджета
Всего сохранено транзакций: 5
```

Ожидаемые отказы в демонстрации не останавливают программу: она продолжает
обработку следующих примеров и завершает работу с кодом 0.

## Проверка ошибок файла вручную

1. Временно переименуйте `budgets.json` и запустите `go run .`.
   Должно появиться сообщение `не удалось открыть budgets.json`.
   Верните исходное имя.
2. Сохраните копию файла, затем уберите из JSON запятую между объектами и
   запустите программу. Должно появиться `не удалось разобрать JSON бюджетов`.
   Восстановите исходный файл.
3. Замените один лимит на `-1` и запустите программу. Ожидается сообщение
   `лимит не должен быть отрицательным`. Восстановите исходный лимит.

Такие ошибки загрузки завершают программу с кодом 1; демонстрационные транзакции
не добавляются. Не оставляйте испорченный файл перед отправкой работы.
