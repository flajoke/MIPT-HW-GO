# Ledger

Service дополнен ImportTransactions(ctx, input, workers). Метод использует jobs/results, N воркеров, WaitGroup и отдельный коллектор. Счётчики accepted/rejected и ошибки защищены sync.Mutex. Канал jobs закрывается отправителем, results — после завершения воркеров; функция ожидает коллектор перед возвратом.

Воркеры вызывают прежний AddTransaction: валидация, бюджет и SQL-транзакция с блокировкой категории. Контекст передаётся во все операции. При отмене возвращаются BulkResult с частичными accepted/rejected/errors/unprocessed и ctx.Err(). Уже сохранённые записи не откатываются; их результаты не теряются при отмене сразу после commit.

По умолчанию 4 воркера, допустимо 1–32. BULK_WORK_DELAY=0s; для демонстрации отмены можно задать 200ms. Слои domain/repository/service/app, фабрика Open, конкурентный отчёт и Redis сохранены.

Из ledger: `go test ./... -race`, `go vet ./...`. Интеграционные проверки включаются через TEST_DATABASE_URL на отдельную мигрированную базу *_test; тесты очищают таблицы. Если C-компилятор не настроен, обычные тесты: `go test ./...`.
