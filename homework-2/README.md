# Домашнее задание 2 — функции, Gateway и Ledger

Два самостоятельных Go-модуля находятся в одном репозитории.

| Папка | Назначение |
| --- | --- |
| `gateway` | HTTP-сервер с маршрутом `GET /ping` на порту 8080 |
| `ledger` | Хранение транзакций в памяти, добавление, проверка суммы и вывод списка |

## Требования

- Go 1.22 или новее: проверьте командой `go version`.
- Свободный порт 8080 для Gateway.
- Используется только стандартная библиотека Go.

Файлы `go.mod` уже включены. Повторять `go mod init` после скачивания не нужно.
Команды запуска нужно выполнять из папки соответствующего сервиса.
Если первое ДЗ лежит в корне репозитория, его файлы можно оставить там.

## Запуск Gateway

Откройте терминал в корне репозитория и выполните:

```sh
cd hw2/gateway
go run .
```

Сообщение перед запуском HTTP-сервера:

```text
Gateway service starting: http://localhost:8080/ping
```

Оставьте этот терминал открытым. Пока сервер работает, он занимает терминал
и ждёт запросов. Для остановки нажмите Ctrl+C.

Откройте в браузере <http://localhost:8080/ping>. Тело ответа должно быть `pong`.

Для проверки статуса и тела в другом терминале Windows PowerShell:

```powershell
curl.exe -i http://localhost:8080/ping
```

В Linux или macOS:

```sh
curl -i http://localhost:8080/ping
```

Проверьте статус `HTTP/1.1 200 OK` и тело `pong`. Заголовки, например `Date`,
могут отличаться при каждом запросе.

Дополнительная проверка в PowerShell:

```powershell
curl.exe -i -X POST http://localhost:8080/ping
curl.exe -i http://localhost:8080/unknown
```

Ожидаются соответственно `405 Method Not Allowed` и `404 Not Found`.
Маршрут `GET /ping` использует синтаксис Go 1.22+. По правилам стандартного
маршрутизатора этот GET-маршрут также обслуживает HEAD-запросы без тела ответа.

## Запуск Ledger

Откройте второй терминал в корне репозитория и выполните:

```sh
cd hw2/ledger
go run .
```

Если второй терминал открылся в `hw2/gateway`, сначала перейдите в соседний сервис
командой `cd ../ledger`, затем выполните `go run .`.

Ожидаемый вывод:

```text
Ledger service started
Ожидаемая ошибка: сумма транзакции не должна быть равна 0
Список транзакций:
ID: 1 | Сумма: 1250 руб. | Категория: Продукты | Описание: Покупка продуктов | Дата: 2026-09-27
ID: 2 | Сумма: 70 руб. | Категория: Транспорт | Описание: Поездка на автобусе | Дата: 2026-09-27
ID: 3 | Сумма: 500 руб. | Категория: Связь | Описание: Оплата мобильной связи | Дата: 2026-09-27
Всего сохранено транзакций: 3
```

После вывода Ledger завершается с кодом 0. Это ожидаемое поведение: в этом ДЗ
Ledger выполняет консольную демонстрацию, а сервер для него пока не нужен.
Строка «Ожидаемая ошибка» показывает успешную проверку запрета нулевой суммы;
ошибочная транзакция не сохраняется.

## Как устроен Ledger

- `Transaction` объединяет ID, сумму, категорию, описание и дату.
- `Amount` имеет тип `int`; единица измерения в этом примере — целый рубль.
- `Date` хранится как строка. В демонстрации используются фиксированные даты.
- `transactions` — срез `[]Transaction`, изначально пустой.
- `AddTransaction(tx Transaction) error` отвергает нулевую сумму, иначе назначает
  ID и добавляет транзакцию через `append`. Успех обозначается значением `nil`.
- ID назначается как `len(transactions) + 1`. Входное поле ID заменяется.
  Такой способ подходит этому ДЗ, поскольку удаления транзакций здесь нет.
- `ListTransactions() []Transaction` возвращает копию среза через `make` и `copy`.
  Изменение элементов полученного списка не меняет хранилище.
- Проверяется только запрет нулевой суммы; ненулевые суммы сохраняются
  с переданным знаком.
- Хранилище существует только в памяти. При следующем запуске оно снова пустое,
  после чего `main` заново добавляет три демонстрационные транзакции.
- Gateway и Ledger на этом этапе работают независимо и не обмениваются данными.

## Инициализация при самостоятельном создании файлов

Этот раздел нужен только если вы создаёте проект вручную и файлов `go.mod` ещё нет.
Для готового проекта из архива эти команды выполнять не нужно.

Из корня репозитория, после создания папок:

```sh
cd hw2/gateway
go mod init hw2/gateway
cd ../ledger
go mod init hw2/ledger
```

`go mod init` создаёт настройки модуля в текущей папке, поэтому каждому сервису
нужен собственный `go.mod`. Во всех вариантах требуется Go 1.22 или новее.

## Отправка работы

Закоммитьте всю папку `hw2`, включая оба `go.mod` и этот README.
Если локальная папка уже связана с репозиторием GitHub, из корня репозитория:

```sh
git status
git add hw2
git commit -m "Add homework 2: Gateway and Ledger"
git push
```

Также можно загрузить папку `hw2` через GitHub: Add file → Upload files.
Загружайте распакованную папку с исходниками. Проверьте, что на сайте видны
`hw2/gateway/main.go`, `hw2/gateway/go.mod`, `hw2/ledger/main.go`,
`hw2/ledger/go.mod` и `hw2/README.md`.

У репозитория должен быть доступ Public. Для сдачи подойдёт ссылка на репозиторий
или его папку `hw2` с этим README и обоими сервисами.

## Если запуск не получился

- `main redeclared`: проверьте, что программы из разных ДЗ не лежат в одной папке.
  Gateway и Ledger должны лежать каждый в своей папке со своим `go.mod`.
- `address already in use` или ошибка Windows о занятом адресе: проверьте,
  не запущен ли Gateway в другом терминале. Остановите свой предыдущий запуск
  через Ctrl+C. Если порт занят другой нужной программой, замените `:8080` на
  `:8081` в `gateway/main.go`, обновите сообщение о запуске и проверяйте порт 8081.
- `go.mod file not found` или запускается первое ДЗ: перейдите в папку нужного
  сервиса, например `hw2/gateway`, и выполните `go run .` там.
- `connection refused`: Gateway должен продолжать работать в первом терминале;
  проверьте ошибки запуска и номер порта.
